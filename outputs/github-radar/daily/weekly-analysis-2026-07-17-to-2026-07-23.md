## 判讀基準

我沒有用總 stars 排名，而是依下列順序打分與降權：

1. **持續動能**：跨日可觀測的累積 stars 成長與出現天數；一次爆紅不如連續 6–7 日成長。
2. **維護證據**：最近 push、release、issue 壓力。活躍但 open issues 很多是「要研究」，不是「可直接採用」。
3. **問題—工作流貼合度**：是否實際支援 Codex/skills/MCP，或能服務 AI 辦公室自動化、課程內容、know metabiz wiki。
4. **可驗證性與採用摩擦**：README 是否說明問題與安裝路徑；授權是否清楚；是否可用小型、可逆 POC 驗證。
5. **安全與範圍降權**：未列授權、會處理敏感資料、全能型大框架、或只是收藏清單，都不因 stars 高而升級為 adopt。

資料邊界：資料夾名稱是 target date，但快照實際在次日台灣時間取得，故比較的是 **7/18–7/24 的七次 API snapshot**。7/17 首日只有 44 筆，其他六日為 89 筆；因此新進候選（如 Obsidian Mind）以其實際被觀測的 5 天計算，沒有假裝擁有完整七日基線。

## 本週可安全忽略或只作情報來源的項目

- `awesome-claude-skills` / `awesome-claude-code`：熱度與發現價值高，但前者 license 空白、後者 `NOASSERTION`；兩者是候選來源，不是依賴。
- Dify、Ruflo、Deer Flow、Multica：功能面很廣的 agent 平台／harness。它們的 stars 說明市場注意力，不代表比既有 Codex + skills 更適合 Adam；除非先有明確多 agent 協作缺口，否則不花導入時間。
- `ai-website-cloner-template`：雖然 +1,296，但「一鍵克隆網站」應先處理 IP、品牌與資安風險；不列為工作流候選。
- `hexstrike-ai`：攻擊性安全自動化範圍太高，和目前產品／內容目標不相稱；不追蹤、不導入。

## 可變成課程與內容的三個題目

1. **從 RAG 到可追溯知識圖**：Graphify POC 講清楚「來源關係」如何讓 agent 的答案可稽核。
2. **Agent context 成本的工程解法**：Headroom 的壓縮，搭配真實 trace 的品質 gate，而不是只展示 token 節省率。
3. **Skills 不是 prompt collection**：用 agent-skills / Loop Engineering / Superpowers 對照「規格、驗證、review、可回復」的工程流程。

## 接下來兩週的觀測 gate

- **Graphify**：若再持續有 release/push，安排隔離 POC；若 evidence link 或權限模型無法滿足，維持研究而不導入。
- **Headroom**：只接受 A/B 後「答案品質不下降且 token 明顯下降」的結果。
- **Obsidian Mind**：先驗證 writeback safety；若不能產生乾淨 diff 或可回復，淘汰。
- **Skills 方法論**：將最有價值的 2–3 個 gate 手動寫入現有技能；成功後才考慮形成新共用 skill。
